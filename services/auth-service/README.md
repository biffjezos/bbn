# auth-service

Issues guest, user, and admin JWTs. Handles registration and login via OPAQUE
(password-authenticated key exchange — no passwords ever reach the server). Handles
admin bootstrap on first boot. All endpoints require a valid `X-Service-Token`
from the gateway.

## Required Environment Variables

| Variable | Notes |
|---|---|
| `JWT_SECRET` | Shared with all services that validate JWTs |
| `SERVICE_SECRET` | Shared secret for inter-service `X-Service-Token` auth |
| `MONGO_URI` | MongoDB connection string |
| `EMAIL_PEPPER` | 32-byte hex string; shared with users-service. Must never change after first use. |
| `OPAQUE_SERVER_SETUP` | Base64-encoded OPRF private key. See install steps below. |

Optional: `DB_NAME` (default `boomboom`), `PORT` (default `8080`),
`ADMIN_BOOTSTRAP_USER_ID` (one-time — see below).

## Behaviour Settings (hardcoded)

| Setting | Value |
|---|---|
| Guest token TTL | 15 min |
| Sessions TTL index | 20 min (MongoDB TTL index on `sessions.createdAt`) |
| Valid tiers | `regular`, `premium`, `unrestricted` |
| Valid roles | `user`, `admin`, `venue_manager` |

## Railway Install

### Step 1 — Deploy without `OPAQUE_SERVER_SETUP`

Set all required env vars **except** `OPAQUE_SERVER_SETUP` and deploy the service.
It will start, immediately print a generated value to the log, and exit with code 1:

```
[auth] FATAL: OPAQUE_SERVER_SETUP is not set.
[auth] A new server setup has been generated.
[auth] Set this env var in Railway and restart:
[auth] OPAQUE_SERVER_SETUP=<base64-string>
```

Copy the full base64 string from the log.

> **Important:** do not reuse a value generated by an older version of this service.
> The cipher suite is `Ristretto255 / TripleDH / Argon2` and requires a 64-byte OPRF
> seed. A value generated by a different cipher suite will cause a panic on startup
> with `SizeError { name: "OPRF seed", ... }`. If you see that error, delete
> `OPAQUE_SERVER_SETUP` from Railway and repeat this step.

### Step 2 — Set `OPAQUE_SERVER_SETUP` in both services

The same value must be set in **two** Railway services:

- `auth-service` → `OPAQUE_SERVER_SETUP=<value>`
- `users-service` → `OPAQUE_SERVER_SETUP=<value>`

Redeploy both after setting it.

### Step 3 — Verify startup

Check the auth-service log. A healthy boot prints:

```
[auth] DB connected.
```

No panics, no `FATAL` lines.

### Step 4 — Admin bootstrap (optional)

To promote an existing user to admin on first boot:

1. Set `ADMIN_BOOTSTRAP_USER_ID=<mongodb-object-id>` in Railway.
2. Redeploy auth-service — it will promote the user on boot.
3. **Remove the variable immediately after** and redeploy again. It is a one-time
   operation; leaving it set is a security risk.

---

## Notes

- `EMAIL_PEPPER` must be identical in auth-service and users-service. Generate once
  with `openssl rand -hex 32` and never rotate it — changing it invalidates all
  existing email hashes and locks out every user.
- `OPAQUE_SERVER_SETUP` contains the server's OPRF private key. Treat it like a
  master secret. If it is lost or changed, all existing `opaqueRecord` blobs become
  invalid and every user must re-register.
