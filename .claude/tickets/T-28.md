## The Problem

The UI is a Jekyll static site on GitHub Pages. Pages are thin HTML shells — all data
is loaded client-side by heavy JS modules. Route guards are client-side scripts (bypassable).
`window.BOOMBOOM_API_URL` is exposed in every page. The browser talks directly to the
Railway-hosted gateway, requiring CORS headers. GitHub Pages adds a separate deployment
pipeline and forces a `/bbn` base path on all URLs.

## Goal

A Rust `server` service that:
1. Serves HTML pages rendered with Tera templates (SSR — inject user context on load)
2. Proxies all `/api/*` and `/ws/*` requests to the gateway (no added logic — pure reverse proxy)
3. Enforces server-side route guards (HTTP 302 redirect for unauthenticated access)
4. Serves all static assets (`/assets/`, `/scripts/`, `/styles/`, WASM, service-worker)
5. Replaces GitHub Pages entirely — all routes served from one origin

## Architecture

```
Browser
  ├── GET /*, /*.html  →  server  (Tera SSR + static files)
  ├── /api/*           →  server  →  gateway  →  microservices
  └── /ws/*            →  server  →  gateway  (WebSocket tunnel)
```

No logic is added to the proxy path. The gateway continues to validate JWTs,
enforce rate limits, and route to microservices — unchanged.

### JWT cookie (required for server-side guards and SSR)

After login, `auth.js` sets `bbn_tok=<jwt>; SameSite=Strict; Secure; Path=/`.
server reads this cookie to:
- Validate access to protected routes (redirect to `/` if missing or expired)
- Extract claims (nickname, tier, role) for template context injection
- Forward the JWT as `Authorization: Bearer <token>` on proxied API calls

On logout, `auth.js` clears the cookie. OPAQUE flow is unchanged.

### Simplified base path

GitHub Pages required `/bbn` as base. With server, base is `/`.
`window.BOOMBOOM_BASE` is eliminated. `window.BOOMBOOM_API_URL` is eliminated
(all API calls go to `/api/*` on the same origin).

## Phase 1 — Scaffold, static serving, API/WS proxy

**Goal:** server runs locally, serves static files, proxies all API and WS traffic.
No templates yet — just file serving and proxy. Smoke-testable end-to-end.

### Implementation

- Create `services/server/` Rust crate, add to workspace `Cargo.toml`
- Dependencies: `axum`, `reqwest`, `tokio`, `tower-http` (ServeDir, compression), `tera`
- Routes:
  - `GET  /api/*`  → reverse proxy to `GATEWAY_URL` (forward method, headers, body, response)
  - `POST /api/*`  → same
  - `PUT /api/*`   → same
  - `DELETE /api/*` → same
  - `PATCH /api/*` → same
  - `GET /ws/*`    → WebSocket tunnel to `GATEWAY_URL`
  - `GET /assets/*`, `/scripts/*`, `/styles/*` → ServeDir from static directory
  - `GET /service-worker.js`, `/manifest.json` → serve from static root
  - `GET /health`  → 200 OK
- Env vars: `GATEWAY_URL`, `GATEWAY_ALLOWED_HOST`, `PORT` (default 8080)
- JWT_SECRET not needed in Phase 1 (no validation yet)
- `Dockerfile.ui` — same pattern as other services
- Verify: all existing API calls work through server proxy

### Definition of done
- `cargo build` passes for server
- `/health` returns 200
- `/api/health` proxied correctly to gateway
- Static files served from `/assets/`
- WebSocket connection to `/ws/location` tunnelled correctly

## Phase 2 — Tera template migration

**Goal:** All pages rendered by Tera. Jekyll/Liquid syntax removed. GitHub Pages
deployment no longer required for page serving (static assets still committed to git for now).

### Tera conversion map

| Liquid | Tera |
|--------|-----------|
| `{% include navbar.html %}` | `{{> navbar}}` |
| `{% if page.title %}{{ page.title }}{% endif %}` | `{{#if title}}{{title}}{{/if}}` |
| `{{ '/' | relative_url }}` | `/` (base is always `/`) |
| `{{ site.api_url \| default: "..." }}` | removed (same-origin `/api/*`) |
| `{{ site.time \| date: '%s' }}` (cache bust) | server injects build timestamp |
| Jekyll frontmatter `---` | removed |

### Template structure

```
services/server/templates/
  base.html                  ← default.html layout
  partials/
    navbar.html
    offcanvas-menu.html
    modal-login.html
    modal-register.html
    modal-pin.html
    modal-lock.html
    modal-delete.html
    modal-tier-gate.html
    modal-block/
  pages/
    index.html
    profile.html
    favourites.html
    messages.html
    messages-thread.html
    settings.html
    admin.html
    donate.html
    profile-view.html
```

### Template context (base, always available)

```json
{
  "asset_version": "20260329",
  "is_logged_in": false,
  "nickname": null,
  "tier": null,
  "role": null,
  "page_title": ""
}
```

Auth context (`is_logged_in`, `nickname`, `tier`, `role`) populated from `bbn_tok` cookie
in Phase 3. In Phase 2 they default to unauthenticated values.

### Route additions

- `GET /`              → render `pages/index.html`
- `GET /profile/`      → render `pages/profile.html`
- `GET /favourites/`   → render `pages/favourites.html`
- `GET /messages/`     → render `pages/messages.html`
- `GET /messages/thread/` → render `pages/messages-thread.html`
- `GET /settings/`     → render `pages/settings.html`
- `GET /admin/`        → render `pages/admin.html`
- `GET /donate/`       → render `pages/donate.html`
- `GET /profile/view/` → render `pages/profile-view.html`

### Client-side changes in Phase 2

- Remove `window.BOOMBOOM_API_URL` — all JS API calls use `/api/` (relative)
- Remove `window.BOOMBOOM_BASE` — all JS path references use `/`
- Update `api.js` to use relative paths

### Definition of done
- All pages render via Tera with no Liquid syntax remaining
- No Jekyll dependency
- API calls from JS work via same-origin `/api/*`

## Phase 3 — Server-side route guards and auth context injection

**Goal:** Protected routes enforced server-side. Client-side guard script removed.
Template renders correct nav state without JS manipulation on first paint.

### Protected routes

| Path prefix | Requirement | Redirect on fail |
|-------------|-------------|-----------------|
| `/messages/` | valid JWT, role in [user, admin, venue_manager] | `GET /` |
| `/favourites/` | valid JWT, role in [user, admin, venue_manager] | `GET /` |
| `/profile/` | valid JWT, role in [user, admin, venue_manager] | `GET /` |
| `/settings/` | valid JWT, role in [user, admin, venue_manager] | `GET /` |
| `/admin/` | valid JWT, role == admin | `GET /` |

### Implementation

- Add `JWT_SECRET` env var to server
- Axum middleware: read `bbn_tok` cookie → decode JWT (no signature re-verify needed if
  HMAC validated; or verify for security) → extract `sub`, `role`, `tier`, `exp`
- If expired or missing on protected route → `302` to `/`
- Inject into template context: `is_logged_in: true`, `nickname`, `tier`, `role`

### Client-side changes in Phase 3

- `auth.js`: on login success, set `document.cookie = 'bbn_tok=<jwt>; SameSite=Strict; Secure; Path=/'`
- `auth.js`: on logout, set `document.cookie = 'bbn_tok=; Max-Age=0; Path=/'`
- Remove inline guard script from `base.html` (the `(function() { ... })()` block)

### Definition of done
- Navigating to `/messages/` without a valid session redirects to `/`
- Navigating to `/admin/` as a non-admin redirects to `/`
- Navbar renders correct logged-in state on first paint (no JS flicker)
- No inline guard script in any template

## Phase 4 — Minimal SSR data injection

**Goal:** Page-specific initial data injected into templates where it saves a visible
loading round-trip. Heavy/real-time data (map markers, conversations list) stays
client-side.

### Injection targets (initial scope)

| Page | Server-injected data | Source endpoint |
|------|---------------------|-----------------|
| `/profile/` | nickname, age, sex, bio (read-only fields) | `GET /api/users/me` |
| `/settings/` | tier, account_type | `GET /api/users/me` |
| All pages | nickname, tier, role (already from JWT — no extra call) | cookie |

Favourites list, conversations list, map markers: remain client-side (dynamic/real-time).

### Implementation

- In page handlers, if `is_logged_in`: call `GET GATEWAY_URL/api/users/me` with
  `Authorization: Bearer <jwt>` forwarded from cookie
- Inject response fields into Tera context
- On gateway error (timeout, 5xx): render page with empty data, JS loads it normally
  (graceful degradation)

### Definition of done
- Profile page shows nickname/tier/bio on first paint without a client JS round-trip
- If gateway is down, page still renders (empty fields, no 500 to browser)
