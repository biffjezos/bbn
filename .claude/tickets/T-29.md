## The Problem

The ES6 module refactor introduced bugs that broke the site. Additionally, after T-28,
much of the existing client-side logic will either move server-side or become unnecessary
(removed `window.BOOMBOOM_API_URL`, `window.BOOMBOOM_BASE`, base-path prefixes, client-side
route guards, etc.). Fixing the broken code before T-28 is waste — we don't know what survives.

## Goal

After T-28 is live: a clean, minimal set of ES6 modules that handles only:
- UI interactions (click handlers, modal triggers, form submissions)
- Real-time features (Leaflet map, WebSocket geo/messages)
- OPAQUE-ke WASM (must stay client-side — crypto)
- Client-side crypto (BBNCrypto)
- Auth state (JWT read from sessionStorage, cookie set/clear on login/logout)

No business logic, no API routing decisions, no page-level data fetching that could
be done server-side.

### Root cause of breakage

The ES6 refactoring exported named modules (`export const Api`, `export const Auth`) and
updated `boomboom.js` to use `import` — but did NOT update the individual modules.
Every module except `favourites.js` still calls `window.Api`, `window.Auth`, `window.BBNCrypto`
as globals, which are never set in an ES6 module context.

`settings.js` is worse: the function bodies were replaced with comment stubs, meaning the
settings page has no working code at all.

## Phase 3 — Remove dead code and simplify

After T-28 Phase 2 is deployed:

- Remove all `window.BOOMBOOM_API_URL` references — API calls use `/api/*`
- Remove all `window.BOOMBOOM_BASE` path prefixes — base is `/`
- Remove inline route guard script (moved to server in T-28 Phase 3)
- Remove any JS that duplicates server-side data injection (T-28 Phase 4)
- Remove `_includes/boomboom.js`, `admin.js`, etc. if confirmed dead
- `api.js`: remove base URL config, use relative paths only

### Definition of done

- No `window.BOOMBOOM_API_URL` or `window.BOOMBOOM_BASE` anywhere
- No inline guard script in any template
- All modules are valid ES6 with correct imports/exports
- Site functions: login, map, favourites, messages, settings all work
- `boomboom.js` imports only from `./lib/`; no `window.*` API calls
