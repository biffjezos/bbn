## The Problem

`ui/scripts/profile.js` contains two complete page implementations:
- `renderMyProfile()` — for `/profile/` (edit own profile, change password, manage venues for venue managers)
- `renderPublicProfile()` — for `/profile/view/?uid=...` (view another user's profile)

Neither function is called. `profile.js` is not loaded by any Tera template. Both pages currently show "Loading…" forever.

The file uses a self-executing pattern designed for legacy `<script>` loading — not ES6 modules.

## Goal

Both profile pages must work:
- `/profile/` — user can view and edit their profile
- `/profile/view/?uid=...` — user can view another user's profile, add/remove favourite, block

## Phase 1 — Convert profile.js to ES6 module

- Add `import { Api } from './api.js'; import { Auth } from './auth.js';` at top
- Replace all `window.Api.*` calls with `Api.*`
- Replace all `window.Auth.*` calls with `Auth.*`
- Replace self-executing init with named exports: `export function initMyProfile()`, `export function initPublicProfile()`
- Remove the self-executing bottom block

## Phase 2 — Wire into boomboom.js

- Import `{ initMyProfile, initPublicProfile }` from `./lib/profile.js`
  (file must be moved to `./lib/` or import from `../profile.js`)
- After `await window.__authReady` in `initApp()`:
  - Call `initMyProfile()` if `#profileFormWrap` is present (only on `/profile/` page)
  - Call `initPublicProfile()` if `#pubProfilePage` is present (only on `/profile/view/` page)

## Notes

- `profile.js` uses `window.BBNCrypto` for password re-encryption — correct name, no change needed
- `window.BlockModule?.prompt()` call in public profile view — `promptBlock` is imported in boomboom.js; expose as `window.BlockModule = { prompt: promptBlock }` or pass as parameter
- `Api.getMyVenues()`, `Api.createVenue()`, `Api.updateVenue()`, `Api.deleteVenue()` are called by venue manager section — these methods are missing from api.js and must be added first
