## Why

`ui/scripts/lib/opaque-client.js` implements the OPAQUE password authentication
protocol (WASM-backed) and the PBKDF2-SHA256 email hash (SEC-1.10 fix). Both
have critical security contracts that are easy to break silently:

- OPAQUE two-step flow (start → finish) for login, register, changePassword
- PBKDF2 email hash: `PBKDF2-SHA256(email, salt='boomboom-email-v2', 100_000 iters)` —
  replacing the old plain SHA-256 (SEC-1.10)
- The client must never send plaintext email or password to the server
- window.OpaqueClient dependency (set by boomboom.js before any auth call)

No spec exists. Without one, future changes to auth flows or email handling risk
reintroducing SEC-1.10 class vulnerabilities.

## Implementation plan

### Phase 1 — Write spec
- Read `ui/scripts/lib/opaque-client.js` in full
- Read `ui/scripts/opaque-client/opaque_client_wasm.js` (WASM bindings, if informative)
- Write `specs/ui/opaque-client.yaml` covering:
  - OPAQUE two-step protocol contract for login/register/changePassword
  - PBKDF2 email hash pre_conditions and expected_behaviour
  - window.OpaqueClient dependency and initialisation
  - What must never cross the wire in plaintext
- Commit spec
