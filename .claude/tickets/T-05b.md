---

## Problem

Block records store a `reason` enum (not sensitive) but have no free-text note field. Adding a plaintext note would be a privacy regression — if the DB is breached, block notes expose relationship context between users.

---

## Approach

Add optional encrypted note field once OPAQUE-based key derivation is confirmed stable. Same key infrastructure as T-24 (Layer 1 keypair + AES-GCM). The blocker encrypts the note client-side before upload; only the blocker can decrypt it.

---

## Notes

- Reason enum is not sensitive and stays unencrypted.
- Coordinate with T-24 Phase 4 (key revocation on block) — same key infrastructure.
